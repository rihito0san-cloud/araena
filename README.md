# MinerPotatos — GPU-флот для аренды на Vast.ai

Локальный контроллер + CUDA-воркеры для майнинга на
[minerpotatos.xyz/mine](https://minerpotatos.xyz/mine). Собрано по спецификации
`MINERPOTATOS_AI_BUILD_GUIDE.md` из
[rihito0san-cloud/araena](https://github.com/rihito0san-cloud/araena).

**Это не готовый бинарник, а исходники.** Гайд сознательно не содержит
исполняемого кода — его надо собрать и проверить на своей машине.

> **Для AI-агентов:** технический контракт и проверенные факты протокола —
> в [`AGENTS.md`](AGENTS.md). Там же список багов, которые уже были найдены и
> исправлены, и инварианты, которые нельзя ломать.

## Что проверено на живой цепи (2026-09-14)

| Параметр | Значение | Как проверено |
|---|---|---|
| Chain ID | `4663` (`0x1237`) | `eth_chainId` |
| Контракт | `0xb0db77c5d6ed578189609ecc72d25699a79f785b` | извлечён из фронтенда |
| Keccak рантайм-байткода | `ec77f042…116c7553` | совпадает с гайдом |
| Функция отправки | `mine(uint256 nonce, uint256 anchorBlock)`, payable | ABI, 158 записей |
| Преимеж | `miner(20) ‖ prevWork(32) ‖ anchor(32) ‖ nonce(32)` = **116 байт** | 6 векторов сверены с `workFor()` контракта |
| Условие солва | `digest <= target` (**включая равенство**) | из воркера сайта |
| `anchor` | = `blockhash(anchorBlock)` | сверено |
| Окно якоря | 250 блоков | реальные минты: лаг 19–126 блоков |
| Цена | читается **при каждой отправке** | `miningStatus().price` |

Преимеж подтверждён не «на веру» по гайду, а против чистой функции самого
контракта `workFor(address,bytes32,bytes32,uint256)` на состоянии, прочитанном
из **одного** закреплённого блока.

### Критичная деталь, которой нет в гайде

`prevWork` и `anchorBlock` меняются **каждый блок**. Если читать
`miningStatus()` и `workFor()` в разных блоках, векторы не сойдутся — и можно
ошибочно решить, что схема преимажа другая. Все проверки в тестах закрепляют
один блок.

## Архитектура

Три границы доверия, как требует гайд:

```
Воркеры (Vast.ai, только CUDA)
   получают: публичный адрес, prevWork, anchor, target, случайный префикс
   возвращают: RATE / FOUND
   никогда не получают: приватный ключ
        │
        ▼
Контроллер  (controller/, 127.0.0.1:8901)
   чтение цепи → выдача заданий → ЛОКАЛЬНАЯ перепроверка каждого пуфа
   → бюджет-леджер → подпись в памяти → отправка → сверка receipt
        │
        ▼
Дашборд  (127.0.0.1:8903, только чтение, свой токен)
   не импортирует signer.py, отклоняет любые изменения
```

Воркер только **предлагает** nonce. Контроллер пересчитывает keccak сам и
сверяет с контрактом перед отправкой. Сломанный или лгущий GPU теряет скорость,
но не может провести плохую транзакцию.

## Установка на сервер Vast.ai

Закиньте папку `minerpotatos/` на сервер (scp, git, или вставкой файлов через
консоль), затем:

```bash
cd minerpotatos
bash deploy/install-on-vast.sh
```

Скрипт:
1. прочитает compute capability из `nvidia-smi` (а не угадает),
2. поставит зависимости из `requirements.txt`,
3. соберёт воркер под конкретную архитектуру,
4. прогонит self-test бинарника,
5. сверит преимаж с живым контрактом.

Если `nvcc` не в PATH (частое на Vast.ai):

```bash
export PATH=/usr/local/cuda/bin:$PATH
```

### Запуск контроллера

```bash
python3 controller/panel.py --binary ./worker/miner --device 0 --device 1
```

Печатает ссылку вида `http://127.0.0.1:8901/#token=…`. Токен — единственная
аутентификация, он только в фрагменте URL (не попадает в логи и Referer).

### Доступ через SSH-туннель

Панель слушает **только 127.0.0.1** — наружу её выставлять нельзя. С вашей
машины:

```bash
ssh -p <ПОРТ> -L 8901:127.0.0.1:8901 -L 8903:127.0.0.1:8903 root@<ХОСТ>
```

Затем открыть локально `http://127.0.0.1:8901/#token=<ТОКЕН>`.

### Дашборд (отдельно, по желанию)

```bash
MP_PANEL_TOKEN=<ТОКЕН_ПАНЕЛИ> python3 controller/dashboard.py
```

## Порядок активации — именно в таком

Ничего не тратится, пока вы не сделаете все три шага:

1. **Кап** — вкладка *Set spending cap*. С нулевым капом леджер **отказывается**
   резервировать, а не подставляет значение по умолчанию.
2. **Ключ** — *Import signer key*. Ключ живёт только в памяти процесса: не
   пишется на диск, не логируется, не уходит на GPU-воркер. В
   `active-signer.json` сохраняется **только публичный адрес**.
3. **Автоотправка** — по умолчанию **выключена**. Кнопка *Submit one proof*
   отправляет один пуф вручную, чтобы вы увидели полный цикл до того, как
   разрешите автоматический.

Отдельный кошелёк под это настоятельно рекомендуется: гайд требует, чтобы
подписант был выделенным, и система не подменяет кошелёк при ошибке.

## Что считается успехом — и что нет

Гайд требует не путать эти состояния, и код их разделяет явно:

| Состояние | Значит |
|---|---|
| `found` | GPU вернул nonce, контроллер его пересчитал |
| `simulated` | `eth_call` с реальной ценой не откатился |
| `signed` | транзакция подписана выбранным ключом |
| `broadcast` | RPC принял байты |
| `included` | есть receipt |
| `mint_confirmed` | **есть Transfer от нулевого адреса на ваш кошелёк** |
| `no_mint_event` | `status=1`, но NFT не получен — это **провал**, газ списан |

Высокий хэшрейт не гарантирует минт: якорь устаревает, цену обгоняют
конкуренты, RPC тормозит.

## Тесты

```bash
cd minerpotatos
python3 -m pytest tests/ -q                 # всё, включая живые проверки
MP_SKIP_LIVE=1 python3 -m pytest tests/ -q  # без сети
```

Плюс отдельный харнесс протокола (нужен собранный бинарник):

```bash
python3 tests/harness.py --binary worker/miner-host --easy --live
```

Харнесс держит stdin открытым и шлёт `QUIT` только после `FOUND`. Просто
`echo -e "JOB ...\nQUIT" | miner` **не является** тестом: воркер корректно
дочитывает буфер до начала хэшинга, поэтому съест `QUIT` и выйдет.

`tests/test_cuda_source.py` type-check'ит CUDA-ветку через `g++` и заглушку
CUDA API — без `nvcc` и без GPU. Это ловит опечатки в ядре и в работе с
памятью устройства ещё до деплоя. Тест правит только синтаксис запуска
`<<<>>>` (его `g++` не понимает) и сам проверяет, что больше ничего не
изменилось, — иначе проверка незаметно съехала бы на копию кода.

Там же regression-guard на реальную гонку, которая одно время была в ядре: ranked
`atomicMin` по старшим словам дайджеста плюс раздельная запись счётчика и
дайджеста позволяли опоздавшему потоку перезаписать пару, составив счётчик
одного кандидата с дайджестом другого. Контроллер бы такое отбраковал, поэтому
симптомом был молча потерянный пуф, а не плохая транзакция.

## Известные ограничения

Честно, без приукрашивания:

- **CUDA-ядро не выполнялось на реальном GPU** — в среде сборки нет ни `nvcc`,
  ни GPU. Что проверено: CUDA-ветка проходит type-check через `g++` с заглушкой
  CUDA API (`tests/test_cuda_source.py`), host-режим собран и протестирован
  целиком — он использует **тот же** `keccak.h` и тот же протокол, а сам keccak
  сверен и с pycryptodome, и с `workFor()` контракта. Что **не** проверено:
  фактический запуск ядра, совместимость `-arch` с вашей картой, геометрия
  запуска. Это подтверждает `build.sh` через self-test на сервере — если
  self-test не прошёл, бинарник не деплоится.
- Не реализован failover RPC на уровне одного запроса (список RPC есть,
  переключение между раундами ретраев).
- Нет автоматической замены/отмены транзакции по цене.
- Нет восстановления при глубоком реорге: ожидание — 2 блока после включения.
- Один глобально ожидающий транзакцию — намеренно, параллелизма по nonce нет.
